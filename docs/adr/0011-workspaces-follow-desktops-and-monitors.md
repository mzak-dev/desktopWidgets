# Workspaces follow virtual desktops through Explorer's registry keys

Several Workspaces can be saved, each with its own Instances and look; one is on screen at a time. A Workspace may be tied to Windows virtual desktops and to a monitor setup, and comes up by itself when the user goes to one of those desktops or connects those monitors.

**The live Workspace keeps its old fields.** `instances`, `theme` and `style` on `Workspace` are the one on screen, so nothing that reads them changed. The others are kept whole in `workspaces`, in the user's order, with `active` naming the one shown; its entry keeps only its name and rules, so `workspace.json` never holds two copies that drift apart. Switching swaps the two, closes every widget window and lets `sync_windows` open the new ones. App-wide settings (GPU, startup, grid, plugins) stay shared. A file from before Workspaces loads as one called Main.

**Which desktop is current comes from the registry.** Windows has no public API that says which virtual desktop is on screen or when that changes: `IVirtualDesktopManager` only answers questions about one window, and the internal interfaces change GUIDs between Windows builds. So, like PowerToys, Wayfinder reads `CurrentVirtualDesktop` (a GUID) under `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\VirtualDesktops`, falling back to `...\Explorer\SessionInfo\<session>\VirtualDesktops` on older Windows 10; the list from `VirtualDesktopIDs` (16 bytes a desktop); a renamed desktop's name from `...\VirtualDesktops\Desktops\{GUID}\Name`. A thread waits on `RegNotifyChangeKeyValue`, not a timer, so following desktops costs nothing until one changes. One switch writes several values, so the app looks 150 ms later and acts only when the current GUID differs.

These keys are undocumented. If a future Windows moves them, every read answers "nothing": no desktop is current, no desktop rule holds, and Workspaces still switch by hand and by monitors. Nothing breaks; the desktop rules stop applying.

**Monitor setups match by name and size, then by size alone.** A rule stores the monitors connected when it was made (`\\.\DISPLAYn`, width, height). The same set fits best; the same number at the same sizes under other names fits too, because Windows renumbers displays when a dock reconnects.

**The most specific rule wins, and a choice by hand stays.** A desktop that holds counts 4, the same monitors 2, renamed ones 1; a Workspace tied to both beats one tied to either, and ties go to the first in order. A Workspace without rules is never picked by itself. Rules are applied at start, when the desktop changes and when displays change, never otherwise, so a Workspace picked from the tray stays until one of those happens. When no rule fits, the one on screen stays.

**Not verified:** widget windows are tool windows (`WS_EX_TOOLWINDOW`), which Windows is said to show on every virtual desktop. Wayfinder does not rely on it: switching rebuilds the windows on the desktop now shown, and staying put when no rule fits works either way. The registry reading, the change thread and the tray submenu have not been run on a real Windows desktop yet.
